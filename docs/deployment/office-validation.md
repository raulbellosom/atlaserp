Mixing these environments is a concrete possible cause that still requires confirmation from the user's device URLs/opening mode. No deployment or environment values were changed.

Existing errors remove the loading cover so recovery remains accessible. Reduced-motion mode disables animation; dark mode uses lighter illustration accents. An isolated browser fixture verified both loading phases, logo loading, unchanged iframe identity/size, rejected unrelated ready messages, the ready transition, session failure, editor timeout, all three formats, light/dark themes, widths from 375 to 1920px and short landscape scrolling. A thin blue/green/orange border identifies DOCX/XLSX/PPTX; the background follows the Atlas theme. An isolated browser fixture verified all three accents, logo loading, download, save acknowledgment, failed-save retry, read-only return, light/dark presentation, and a 375px layout retaining the 46px header and 44px controls. This fixture tests host UI/message behavior, not document fidelity. Web build, targeted ESLint, message-origin test and diff checks passed. React Doctor scored 93/100 with no errors and one warning about related state variables in OfficeDocumentEditor.

Open fidelity issue — original examined: the user supplied the 130,752-byte quotation DOCX. ZIP CRC verification passed and its main document XML parsed successfully; these checks do not constitute full OOXML schema validation. The XML contains two tables, two anchored drawings, three inline drawings, four AlternateContent blocks, grouped VML shapes with absolute positioning, and 56 text-box-content nodes (including compatibility representations, not necessarily 56 distinct visible boxes). Explicit run fonts reference Arial. These structures support an import/layout compatibility diagnosis; a PDF-to-Word origin is not established by the metadata.

Reproduction: submitted the original directly to the existing local `collabora/code:26.04.2.4.1` conversion API, producing PDF and PNG without Atlas UI, WOPI or Storage. Visual inspection of the PNG reproduced the detached purple shape, client panel overlapping the dark header, missing header text and invisible second item row. This isolates the observed rendering problem to CODE's handling of this document rather than Atlas header CSS or the WOPI save path. The original remains untouched; private source/render artifacts are not committed. Collabora's [documented import limitations](https://help.collaboraoffice.com/24.04/en-US/text/shared/guide/ms_import_export_limitations.html) include shapes, tables and frames. A compatible editable quotation would require a separate layout reconstruction using normal paragraphs/tables and inline images, followed by comparison in Word and CODE; blanket conversion or font replacement is not a verified fix. Comparing an actual saved DOCX with the original remains pending; no original-document preservation or fidelity fix is claimed.

The 22 installer tests passed, including the eight Compose profile/platform combinations and persisted Office settings. The VPS guide now separates image publication, bootstrap refresh, initial DNS/TLS configuration and subsequent updates. This follow-up was checked locally; it has not been deployed to a VPS.

The unchanged Supabase storage client calls are exercised through injected fixtures.

DOCX/XLSX/PPTX structure validation has automated coverage; the full browser editing/collaboration test used XLSX. Complex Word/PowerPoint fidelity, production fonts, heavy spreadsheets, load limits, real iOS Safari, real Android, installed PWA and the native Tauri WebView still need deployment acceptance. Tauri binaries were built, but their embedded editor was not interactively tested. Future mobile WebViews are not certified by these checks.
